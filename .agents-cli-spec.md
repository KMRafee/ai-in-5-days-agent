# Agent Spec

## Overview
An "AI in 5 Days" Content Customizer Agent built with an ADK 2.0 graph-based `Workflow` (`google.adk.workflow.Workflow`) using `gemini-3.8-flash`. The agent scaffolds a local training PDF workspace (`./content_pdfs/day1` through `day5`), collects or restores the learner's profile (`user_name`, `user_email`, `technical_track`, `target_day`) via a conversational `RequestInput` loop (`setup_session`), extracts training material from the target day's PDF using `pypdf` (`pdf_reader`), personalizes an engaging daily brief with curiosity hooks and micro-challenges (`content_summarizer`), pauses for explicit human-in-the-loop review (`human_review`), and conditionally dispatches approved briefs via Email and a Google Chat Space Card v2 webhook (`dispatch_brief`).

## Language
`python`

## Architecture & Workflow Nodes
1. **`setup_session`** (`@node(rerun_on_resume=True)`):
   - Checks `ctx.state` and `node_input` for `user_name`, `user_email`, `technical_track` (`Engineer` or `Architect`), and `target_day` (`day1`–`day5`).
   - Uses a conversational `RequestInput` loop (`interrupt_id`s: `ask_user_name`, `ask_user_email`, `ask_technical_track`, `ask_target_day`) for any missing fields and persists the validated profile into `WorkflowState` via `Event(state=...)`.
2. **`init_workspace`** (`FunctionNode`):
   - Creates local directories `./content_pdfs/day1` through `./content_pdfs/day5` if they do not exist.
   - Seeds a valid starter training PDF in the target day's folder if no PDF is present so automated runs and evaluations always have a readable PDF, and emits guidance on where users can drop custom PDFs.
3. **`pdf_reader`** (`FunctionNode`):
   - Discovers the `.pdf` file in `./content_pdfs/{target_day}`, extracts text and page metadata using `pypdf`, and validates the output against a strict `ExtractedPdfContent` Pydantic schema.
4. **`content_summarizer`** (`LlmAgent` / `Agent` with `gemini-3.8-flash`):
   - Accepts `SummarizerInput` (`input_schema`) and outputs `DailyBrief` (`output_schema`) personalized to the learner's `technical_track` (`Engineer` vs. `Architect`), complete with `title`, `executive_summary`, `key_takeaways`, `curiosity_hooks`, and `micro_challenge`.
5. **`human_review`** (`@node(rerun_on_resume=True)`):
   - Displays the formatted `DailyBrief` in the CLI/UI and pauses with `RequestInput` for explicit human confirmation (`approve` or `reject`), then emits `Event(route="APPROVED" | "REJECTED")`.
6. **`dispatch_brief`** (`LlmAgent` / `FunctionNode` on `APPROVED` route) & **`cancel_dispatch`** (on `REJECTED` route):
   - On `APPROVED`: invokes `send_email_brief` and `post_google_chat_card` tools to dispatch the confirmed brief to the user's email and Google Chat Space webhook.
   - On `REJECTED`: logs the rejection and halts safely without calling any external dispatch tools.

## Example Use Cases
1. **Interactive Multi-Turn Session Setup & Approved Dispatch**:
   - Input: User starts a session with `"Start my AI in 5 Days brief"`.
   - Flow: `setup_session` prompts via `RequestInput` for Name (`"Alex Rivera"`), Email (`"alex@example.com"`), Track (`"Architect"`), and Day (`"day1"`). `init_workspace` prepares `./content_pdfs/day1`, `pdf_reader` extracts the Day 1 PDF with `pypdf`, `content_summarizer` generates an Architect-focused brief with curiosity hooks and a micro-challenge, and `human_review` pauses via `RequestInput`. User responds `"approve"`, routing to `dispatch_brief` which sends the email and posts a Google Chat Card v2 payload.
2. **Pre-Populated Profile & Rejected Review (Safety Gate)**:
   - Input: User provides `"Generate Day 2 brief for Sam Chen (sam@company.com), track: Engineer"`.
   - Flow: `setup_session` extracts the profile from the prompt without redundant interrupts, `init_workspace` and `pdf_reader` extract the Day 2 PDF, `content_summarizer` creates an Engineer-focused brief, and `human_review` pauses via `RequestInput`. User responds `"reject"`, routing to `cancel_dispatch` so neither `send_email_brief` nor `post_google_chat_card` is executed.

## Tools Required
- `send_email_brief(recipient_email: str, user_name: str, day: str, track: str, subject: str, body_markdown: str) -> dict`:
  - Sends the confirmed daily brief to the collected user email via SMTP (when `SMTP_HOST` / credentials are configured) or executes a structured dry-run dispatch with JSON telemetry logging when credentials are unset.
- `post_google_chat_card(webhook_url: str, user_name: str, day: str, track: str, title: str, summary: str, curiosity_hook: str, micro_challenge: str) -> dict`:
  - Posts an interactive Google Chat Card v2 payload to `GOOGLE_CHAT_WEBHOOK_URL` (or executes a validated Card v2 payload dry-run with structured JSON telemetry logging if no live webhook URL is configured).
- `extract_pdf_from_workspace(target_day: str, workspace_root: str = "./content_pdfs") -> ExtractedPdfContent`:
  - Uses `pypdf.PdfReader` to extract text, page count, and file metadata into a strict Pydantic model.

## Constraints & Safety Rules
- External dispatch tools (`send_email_brief`, `post_google_chat_card`) MUST NEVER be called unless the human explicitly approves the drafted summary at the `human_review` `RequestInput` gate.
- All workflow node I/O and LLM agent boundaries must use strict Pydantic `BaseModel` schemas (`WorkflowState`, `UserProfile`, `ExtractedPdfContent`, `SummarizerInput`, `DailyBrief`, `DispatchReceipt`).
- Every node and tool must emit structured JSON observability logs (`severity`, `node`, `event_type`, `message`) compatible with Cloud Logging and Cloud Trace.
- Model must be set to `gemini-3.8-flash`.

## Success Criteria
- `init_workspace` creates `./content_pdfs/day1` through `./content_pdfs/day5` and ensures a valid PDF exists in the target day directory.
- `pdf_reader` extracts non-empty text using `pypdf` and returns a validated `ExtractedPdfContent` Pydantic model.
- `content_summarizer` produces a track-tailored `DailyBrief` containing at least 1 curiosity hook and 1 concrete micro-challenge.
- `human_review` pauses execution via `RequestInput` and routes `"approve"` to `dispatch_brief` and `"reject"` to `cancel_dispatch` (0 external tool calls on reject).
- Unit tests (`uv run pytest`) and behavioral evaluations (`agents-cli eval run`) pass cleanly.
